# PR Review Log #25

https://github.com/hexuria/hyper-use/pull/25

## Summary
- Scope: compact-snapshot observe. One `Runtime.evaluate` tags elements with `data-hu-k` and returns rect, style, and hit for each one, replacing about 4 CDP calls per node.
- Risk: **High**. It changes the evidence the hard gate uses to judge occlusion, on the world boundary, and observe now writes to the page DOM.
- Note: self-review. The author of the PR (Devin) wrote this review.
- Positives:
  - The fallback design holds: untagged elements, and fixtures without the eval step, take the exact legacy per-node path. Existing fixtures are unchanged.
  - The join is by attribute, so no reliance on walk order. Shadow and iframe walk coverage are kept.
  - The tests cover the 5-call budget, a mixed-coverage path, throw handling, and blob decoding. The live test shows the walk runs on real Chrome.
- Concerns (see inline comments):
  1. **[blocker]** Shadow retargeting: `elementFromPoint` returns the shadow host, so `owns_hit` falsely marks every clickable inside an open shadow root as occluded. Regression on ADR 0007.
  2. **[major]** Iframe content is hit-tested from the iframe's own document, so parent-document overlays are missed. This under-reports occlusion, which is the unsafe direction.
  3. **[major]** A thrown eval aborts observe, and page JS can trigger that. It should fall back to the per-node path.
  4. **[major]** DOM side effect: attributes are visible to the page and persist, and a `cloneNode` can copy a tag (duplicate k). Needs duplicate detection and an ADR note.
  5. **[major]** Style and hit are computed for every element, so eval time and payload grow with the whole DOM rather than with the candidates.
  6. **[minor]** The live test checks labels only. Fixtures never run `COMPACT_JS`, so the tests compare Rust against Rust. Needs a live parity test that includes flags.
  7. **[nit]** `h as u32` truncation, and `compact::parse` has no fuzz target.
- Not verified: these findings come from reading the code against `owns_hit` and the legacy path. Per the review playbook, nothing was executed.

## Decision
Request changes. GitHub won't let the PR author submit Request changes on their own PR, so this is posted as a comment.

## Next steps
1. Fix the shadow descent in `hitAt`, and hit-test from the top document (concerns 1–2).
2. Fall back to per-node on eval throw (3).
3. Detect duplicate `data-hu-k` in `walk_dom`, and document the DOM injection in an ADR and AGENTS.md rule 7b (4).
4. Limit `s`/`h` to keep candidates (5).
5. Add a live parity test comparing compact and legacy manifolds, flags included, on a shadow/iframe/overlay page (6).
6. Add `u32::try_from` and a fuzz target for `compact::parse` (7).

# PR Review Log #24

https://github.com/hexuria/hyper-use/pull/24

## Summary
- Scope: `--policy jev`. `TypesafeTransport` turns the offered `ActionSpace` into jev's single-request "operation + per-kind target" questions, then validates the answers back into the closed `{"choice":{"id","kind"}}` reply.
- Risk: **Medium**. The new policy path stays behind a feature flag, the wire contract and gate/ticket chain are unchanged, and PUA remains the default.
- Note: self-review. The author of the PR (Devin) wrote this review.
- Positives:
  - Rule 8 (closed remote reply) holds: JEV can only return an offered criteria key, and `parse_reply` re-validates the reply.
  - `validate_choice` matches jev's checks: off-menu choice, coverage, finite values in [0,1], sum ≈ 1, argmax.
  - The cfg-paired `predict_jev`/`drive_jev` give a clear error when the feature isn't built. Generic `drive_with` has no product-path edits.
  - Rustdoc `-D warnings` fixes on main are included.
- Concerns (see inline comments):
  1. **[major]** The `call()` mapping from answers to reply (missing target head, wrong head) has no tests. Extract a pure `reply_from` and table-test it.
  2. **[major]** CI only `cargo check`s `--features jev`, so the typesafe tests never run.
  3. **[minor]** The round-trip test doesn't cover `TYPE_TEXT`/`SELECT` id composition.
  4. **[minor]** No request timeout or bounded decision retry, so one 5xx ends the run. `from_env` errors are labelled `CliError::Browser`. `TEXT_MODEL_*` parity isn't wired, and the docs should say so.

## Decision
Request changes (small). GitHub won't let the PR author submit Request changes on their own PR, so this is posted as a comment. Nothing here is a blocker for safety. The two majors are test and CI gaps on the new path.

## Next steps
1. Extract and table-test `reply_from` (1).
2. Add `cargo test` and `clippy -D warnings` with `-p hyper-use-cli --features jev` to CI (2).
3. Extend the round-trip fixture to TYPE_TEXT, SELECT, and SCROLL_* (3).
4. Add a timeout and one decision retry, fix the error variant, and add a doc note on TEXT_MODEL_* (4).
